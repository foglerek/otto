# Release Policy

This document defines the release cut policy for Otto packages.

## Branch Policy

- Release automation runs from `main` only.
- Pull requests must pass `changeset-check` and `release-dry-run` before merge.

## Release Modes

The release workflow evaluates one of three modes via `scripts/release/evaluate-mode.mjs`:

- `prepare`:
  - `.changeset/*.md` files are present.
  - Workflow runs Changesets action to maintain or create the release PR.
- `publish`:
  - No pending changeset markdown files.
  - HEAD subject matches `Version Packages...` (release PR merge commit).
  - Workflow runs publish path (`bun run release`) with provenance.
- `none`:
  - No pending changesets and no release-cut commit.
  - Workflow exits without release action.

## Publication Gating

- `NPM_TOKEN` is required for release workflow execution.
- Full repo validation must pass in CI before version/publish steps:
  - `bun run lint`
  - `bun run typecheck`
  - `bun run test`
  - `bun run build`
- Release workflow uses protected `release` environment and OIDC provenance (`NPM_CONFIG_PROVENANCE=true`).

## Release Cut Criteria

A publish cut is valid only when all are true:

1. Merge is on `main`.
2. Release commit is generated by Changesets (`Version Packages` commit).
3. Repository validation passes in release workflow.
4. Required publishing secret (`NPM_TOKEN`) is present.

## Operational Notes

- For normal feature merges with pending changesets, release workflow stays in `prepare` mode.
- If no releasable state exists, workflow reports `none` and does not attempt version/publish.
